# Our Swear Jar 🤬

A shared swear counter for two people, with optional comments and playful milestone challenges.

[Open Our Swear Jar](https://brilliant-parfait-aaffec.netlify.app/)

## Features

- Track separate totals for “She” and “He.”
- Add an optional comment with each entry.
- View timestamped history, delete an entry, or clear the history.
- Show a random challenge when a person's count reaches a multiple of 20 after adding an entry.
- Generate another challenge from the built-in list.

## How it works

The entire app lives in `index.html`: HTML, CSS, and vanilla JavaScript. It uses the browser's Fetch API to read and write records through Supabase's REST API. Netlify hosts the page and is connected to this repository.

There are no package dependencies or build steps. Totals are calculated from the records returned by the database, so deleting entries changes the counts. Challenges are chosen in the browser and are not saved to the database.

## Run locally

With Python 3 installed, run this from the repository folder:

```sh
python3 -m http.server 8000
```

Open [localhost:8000](http://localhost:8000). Internet access is required for Supabase.

The checked-in page points to the live database. For a separate copy or development environment, change `BASE` and `KEY` in `index.html` to your own Supabase project before adding or deleting data.

## Database setup

The code expects a `swears` table with these columns:

| Column | Use |
| --- | --- |
| `id` | Numeric record identifier, generated by the database. |
| `person` | “She” or “He”; older “Me” and “Him” values are also recognized. |
| `word` | Optional comment; may be null. |
| `created_at` | Timestamp generated by the database. |

Database schema migrations and access policies are not included in this repository. Configure these in your own Supabase project. The app has no sign-in flow; access is controlled by the database's permissions and row-level security policies. Use a browser-safe publishable key, never a secret or service-role key.

## Deploy and edit

Edit `index.html`, commit, and push to `main`. The connected Netlify project can deploy changes automatically. For a new static Netlify site, publish the repository root and leave the build command empty.

Edit the `PUNISHMENTS` array to customize the milestone challenges. Swear history lives in Supabase, not in Git; cloning the repository does not copy the database.
